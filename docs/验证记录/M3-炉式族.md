# M3 验证记录：炉式族（T4 路由）

- 日期：2026-10-17
- 出口判据：映射表生效 + 食物过滤正确 + 排除可配（真机抽验待人工）

## 设计定稿（实证驱动）

- **路由默认目标 = 原版炉自身**（furnace/smoker/blast_furnace）：自带燃料机制、Container API 公开（javap 实证 `AbstractFurnaceBlockEntity.isFuel` public static、`AbstractFurnaceBlock.LIT` 属性）、环境必有。v5 设想的「旋风烤肉塔等 modded 方块」保留为 config 路由行（furnaceRouting.routingRules），M3 不做通用 modded BE 驱动猜测——映射到非原版炉的目标由真机验证暴露问题后逐个实证（记 M5 长尾）。
- **食物过滤**：`DataComponents.FOOD` 组件判据（1.21.1 无 CONSUMABLE 组件于该路径，javap 校正）；烧炼 574/烟熏 241/高炉 175 中仅可食产物进点单。
- **燃料**：炉未点燃且燃料槽空时自动投 1 个 `isFuel` 物品。
- **营火不接**（本体 ToasterCookTask 已覆盖，覆盖质量缺口按 v5 另立议题）。

## 任务类

`AbstractFurnaceRoutingCookTask<T extends AbstractCookingRecipe>`（T4 基类：映射表扫描优先、原版炉回落、盒扫+占用、食物过滤出口）+ `FurnaceRoutingCookTasks.Smelting/Smoking/Blasting` 三实类。UID 按 `FurnaceRoutingCookTask.<type键>` 区分。

## 构建

`gradlew build` 绿。

## 真机抽验操作单（待人工）

1. 熔炉旁下单任一**可食烧炼产物**（如烤马铃薯）：女仆投料+补燃料（无燃料时报待料不卡死）→ 取出 → 上菜。
2. 烟熏炉：下单一道烟熏鱼。
3. 高炉：确认点单菜单**不含**矿石/金属锭（食物过滤生效）。
4. config：往 routingRules 填一行 `minecraft:smelting=<某modded烤方块id>` 重进存档，确认扫描改道（modded 驱动兼容性如实记录）。
