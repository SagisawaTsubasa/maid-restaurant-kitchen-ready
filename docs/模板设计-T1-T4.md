# 四大模板设计（M1 定型，随 M2-M4 实例化回填）

依据：实施计划 v5 §四 + 本包反编译实证修订。每模板注明「实证基础」与「首个实例」。

## T1 复用改键 → **修订为「继承 + 状态机换键复制」**

> **2026-10-22 回滚注记**：flex 两类（flex_pot 47 条/flex_stockpot 51 条）永不接（用户决议，见 docs/边界清单.md「永不接决议」节），实例类 FlexPotCookTask/FlexStockpotCookTask 已随 0.2.4 整删——本节仅存设计留痕，原设计内容不重写。

- 计划原案：内置任务子类只改 `getType()` 返回 flex 键。
- 实证修订（2026-10-17）：`FlexPotRecipe`/`FlexStockpotRecipe` 与 `PotRecipe`/`StockpotRecipe` 互不继承（final Record），父类 `cookTick` 状态机硬编码 `byKeyTyped(POT_RECIPE/STOCKPOT_RECIPE, id)`，flex 配方查不到 → `.value()` NPE；且 tickState 为 private 不可覆写。
- 落地形态：子类继承任务（免费继承 searchWorkBlock/isValidWorkBlock/getCurrentInput/getIcon/getKitchenWares），覆写 `getUID/getType/getIngredients/cookTick/getAllRecipeData`，状态机复制时仅换 RecipeType 与配方类。**BE 端原生支持 flex**（PotBlockEntity.startCooking / StockpotBlockEntity.flexQuickCheck），女仆投料后由 BE 自匹配。
- 实例：`FlexPotCookTask`（flex_pot 47 条）、`FlexStockpotCookTask`（flex_stockpot 51 条）。
- 时机坑：森罗 `ModRecipes.FLEX_*` 字段在 `register(RegisterEvent)` 赋值（构造期为 null）——构造期禁止调 `getType()`（注册器日志已改记 UID）。

## T2 同构模板（复制 CookingPotCookTask 结构改 BE 类型与进料槽）

- 实证基础：本体内置 `CookingPotCookTask`（FD 烹饪锅）= 「搜索 POI→验 BE→状态机投料/烹饪/取餐」的最通用同构体；目标 mod 的锅类 BE（怪物锅/农艺 pot·stove·roaster/家具煎锅烤箱微波炉）均呈同构接口。
- 落地形态：逐目标 mod 复制状态机改 `(TargetBlockEntity)` 判定、进料槽位、取餐路径；公共骨架不强行抽象（各 BE 接口差异大，实证后决定是否上抽基类）。
- 首个实例：M4 怪物锅（monster_pot，70 条）。实例化前必反编译该 BE 全接口。

## T3 定时容器模板（放料→计时→取货）

- 实证基础：目标家族（腌菜罐/竹匾/冰箱/木盆/醒发箱/筒仓/冰柜/茶壶/米饭碗/煨茶壶）多为「inventory BE + tick 计时 + 完成态取货」，部分带流体注入/品质/温档/露天/开盖变体。
- 落地形态：M2 首个实例（腌菜罐或竹匾）反编译后抽出最小骨架（若各 BE 确有公共形态）；变体挂点按实证逐个接，不预造空钩子。
- 关键差异预警：竹匾是翻面/阶段制（BambooTrayRecipe$Subtype）、腌菜罐是发酵时长制——首例实证前不写死骨架。

## T4 自定义搜索（炉式映射路由）

- 实证基础：烧炼/烟熏/高炉三类配方本无「工作方块」概念，映射表给定目标方块（旋风烤肉塔等）后走 Box 扫描 + `BlockUsageManager` 占用对齐，不走本体 POI。
- 落地形态：读 `Config.FURNACE_ROUTING_RULES`（`FurnaceRouting.rules()` 加载器 M1 已就位）→ searchWorkBlock 自定义 Box 扫描目标 BE → cookTick 驱动。食物过滤（产物 id/标签）在 getAllRecipeData 出口（RecipeDataFilter 之后接食物谓词）。
- 首个实例：M3。前置：嵌套包扫描 `packs/*/data/` 枚举在场烤/熏方块 BE 候选表。
